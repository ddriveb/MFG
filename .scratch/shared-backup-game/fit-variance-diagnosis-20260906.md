# Fit 高标准误诊断 — 2026-09-06

Status: completed retrospective diagnosis; original campaign remains fit_no_candidate.

## 结论

主要原因是小样本的 F 尾风险估计与预算驱动的路径间异质效果叠加，
不是本次检查发现了 jackknife 漏除样本数、CRN 失配或工作成本异常。
在 NSNS 对 NSSS 的关键比较中，两个公共路径贡献92.29%的 jackknife 方差；
F CVaR 项贡献77.67%，D/F CVaR 两项合计89.76%。两条规则的总体成本差仅0.106。

这里1.70–1.91是配对成本差的估计标准误，不是单次服务时间的方差。
固定点重复出现说明同一 Fit 数据上的最佳响应映射稳定，不能替代统计精度。

- 复核全部32条原 Fit trace fingerprint，一致；未生成 Validation 工作负载。
- 仅重放原 Fit 的6个配置、各32场景：192次额外诊断 scheduler calls。
  配置按“其他玩家规则/Expert0规则”记为 NSNS/NSNS、NSNS/NSSS、NSNS/NSND、
  NSNS/NNDX、NNNN/NNNN、NNNN/NSNS。每次均重跑完整共享物理过程。
- 6个 pooled objective 与96个配对 delete-one 值复现到绝对误差1e-10以内。
- 原 fit.json、manifest.json、result.json 的 SHA-256 在诊断前后不变。
- 192次为单独记账的拟合数据诊断；正式 Fit 49344、Validation0及原先57568次
  两轮正式执行累计记录保持不变。未扩充样本、修改阈值、产生 candidate 或重启 Fit。

## 2. 有效样本远少于 scheduler 调用次数

Fit 使用16条公共故障路径，每条2个人口样本。每个偏离规则仅计分 Expert0，
另外7个 Expert 参与竞争但其请求不会作为该偏离玩家的额外收益样本。
Expert0合计5250个请求，其中：

| 到达阶段 | Regular | Urgent | 合计 | CVaR95尾部质量 |
| --- | ---: | ---: | ---: | ---: |
| D | 1236 | 293 | 1529 | 76.45个请求 |
| F | 244 | 52 | 296 | 14.8个请求 |

F尾部只有约15个请求的质量，而且同一路径/人口中的请求共享队列和 Replay 冲击。
这些不能被当成15个独立尾部实验，32场景也不能被当成32个独立公共路径。

三个起点共用相同32条 Fit traces。三次到达 NSNS 时，整个256规则表完全重复，
不是三份独立的精度证据。49344次调用主要用于不同策略反事实和重复起点，
并没有把顶层独立公共路径数从16增加到49344。

## 3. 两个精度门都失败，且关键竞争规则确实不确定

Fit 门要求所有候选相对 incumbent 的最大 SE <=0.1804936734，
并要求第一名相对第二名的成本差 >2倍配对 SE。

| 所处环境 | 最佳/次优 | 成本差 | 最佳/次优 SE | 最大候选 SE |
| --- | --- | ---: | ---: | ---: |
| NNNN | NSNS / NSND | 0.113847 | 0.080271 | 1.914692 |
| NSSN | NSNS / NSND | 0.100994 | 0.049344 | 1.882282 |
| XXXX | NSNS / NSND | 0.115610 | 0.066783 | 1.705573 |
| NSNS（3个起点相同） | NSNS / NSSS | 0.105985 | 1.645794 | 1.898358 |

在最终 NSNS 环境中：

- NSNS：J=26.055814720。
- NSSS：J=26.161799863，差0.105985142，但 SE=1.645794108。
- NSND：J=26.176020466，差0.120205746，SE仅0.059860160。
- 最大 SE 来自 NNDX，J=28.409602463，SE=1.898358217。
- 256条规则中仅4条相对 incumbent 的 SE 不超过目标。

所以不能仅将问题归咎于“全表最大 SE 被无关的坏规则拖累”：
真正的次优 NSSS 自身也有很大的不确定性。删除任一路径后重新查看原规则表，
16次中有4次第一名从 NSNS 变成 NSSS（common8、10、12、13）。这只是影响分析，
没有用它修改正式选择。

## 4. 成本差的方差几乎来自尾延迟

定义 Delta=J(NSSS;其他人NSNS)-J(NSNS;其他人NSNS)。正值表示 NSNS 更好。
全样本 Delta=0.105985142。逐项 delete-one 重算得到：

| 目标中的加权项 | 全样本 Delta | 该项 SE | 对总方差贡献 |
| --- | ---: | ---: | ---: |
| F CVaR /2 | 0.003323 | 1.310874 | 77.67% |
| D CVaR /2 | 0.102555 | 0.272771 | 12.09% |
| F phase loss /4 | -0.171746 | 0.173628 | 7.23% |
| D phase loss /4 | 0.150951 | 0.109880 | 2.97% |
| executed work per Token | 0.009577 | 0.002692 | 0.021% |
| wasted work per Token | 0.011324 | 0.002658 | 0.018% |

H/R加权阶段损失的配对差和SE均为0。表中的方差贡献使用
Cov(delete-one component, delete-one total)/Var(delete-one total)，因此纳入
相关项并且合计100%；不是把有相关性的各项方差直接相加。

NSNS 的 D/F尾风险项占整个 J 的71.18%。所以少数 F 尾请求对排序影响很大。
注意 F CVaR 的全样本差几乎为0，不代表该差稳定：它包含相反路径效应的抵消。

## 5. 两条路径如何制造相反效应

下表使用真实 common_episode_id，不是按 hash 排序的 delete-one 向量下标。
向量下标8对应 common2；下标14对应 common13。

| 影响分析 | Delta（NSSS-NSNS） | 该路径占 jackknife 方差 |
| --- | ---: | ---: |
| 全部16路径 | +0.105985 | — |
| 删除 common2 | +1.256868 | 47.00% |
| 删除 common13 | -1.052322 | 45.29% |

两个共同路径合计92.29%。其效果在某一个人口样本特别明显，不能仅凭这16×2
样本就断言所有方差来自公共故障、而不是本地到达与服务随机性及其交互。

### common2 / population0：增加 Regular 保护有效降低积压

故障时间197.145139，恢复223.673506。
NSNS 在 D 后半段只保护 Urgent；NSSS 也向 Regular 申请保护。

- NSSS 保护了175.14、176.70到达的两个 Regular，请求延迟分别减少约15.07、15.46。
- 该场景 Expert0 的 D-arrival Replay 数从8降到6。
- F平均延迟从14.019降至11.503；F最大延迟从22.426降至18.871。
- 也有代价：168.73到达的 Urgent 被先到 Regular 用完额度后拒绝，延迟增加14.915。

整体上，这条路径提供了有利于 NSSS 的故障恢复效果。

### common13 / population1：Regular 提前用尽额度，错失临近故障的 Urgent

故障时间224.238162，恢复247.758036。

- NSSS 在[200,225)窗口于201.25、201.80批准两个 Regular，额度随后不足1。
- 206.53、214.09到达的 Urgent 因此被拒绝；NSNS 会批准它们。
- 214.09的 Urgent 在 NSSS 下增加16.718延迟，并从无 Replay 变为 Replay。
- Expert0 的 D-arrival Replay 从7增至10。
- F平均延迟从8.502升至11.071；F最大延迟从14.715升至20.646。
- 同一 common13 的 population0 也出现两个晚 Urgent 被挤掉、Replay0变2。

这些都是同一 CRN 场景下完整有限系统的反事实记录。它们展示了
“先到 Regular 抢占本地保护许可 -> 临近故障保护不同 -> Replay和共享排队不同”
的可见链条。没有另做拆除共享瓶颈的消融，因此不能把全部延迟差单独归给
共享算力，也不能把预算效应与队列取消效应完全分离。

在 NSNS 的 F 尾部，common2占47.30%的尾质量；换成 NSSS 后，common13占40.54%。
政策改变了尾部由哪些路径构成，因而 CRN 无法把它们当作共同加性噪声消掉。

## 6. 未发现配对/公式错误；但近似推断仍有局限

- 原始 trace hash 完全相同，自己的无偏离行16个配对差全部为0。
- Worker 和 baseline 都按相同 fault fingerprint 删除整条路径的两个 population，
  没有错位配对。6个诊断配置逐项复现了原始点估计和配对差。
- 最佳/次优 SE 是配对差的 jackknife，不是把两个独立 SE 平方相加。
  NSNS/NSSS 的配对 SE=1.646；忽略配对的比较值约2.941。
  NSNS/NSND 的配对 SE=0.05986，而不配对约3.349，说明 CRN 在此工作正常。
- delete-one估计之间共享绝大多数样本，不能把它们当成16个独立成本，
  再用普通样本均值SE公式除以sqrt(16)。正式 jackknife 使用
  sqrt(15/16 * sum((d_minus_c-mean)^2))，本次独立复算一致。

CVaR尾部与仅16条顶层路径使 jackknife 数值本身也可能不稳定。
本诊断验证了实施公式和样本敏感性，没有证明其小样本置信区间覆盖率。
不要把1.646当成已精确知道的总体标准误。

## 7. 后续建议及不应采取的捷径

1. 保留此次 fit_no_candidate；不重复相同三起点来试图增加独立样本数。
2. 下一协议先安排方差/精度试验，比较增加公共路径和增加路径内独立人口样本的
   收益。仅有2个嵌套人口不足以稳定估计两层方差贡献。
3. 可在新协议中对已知故障时长分布分层，并保持正确权重；队列负载的个体
   随机性也需覆盖。不得删除 common2/13 或事后只选择有利时段。
4. 区分“识别唯一的样本最佳规则”和“限制所有偏离收益”。epsilon-Nash不要求
   严格识别唯一第一名；新协议可围绕偏离收益的同时上界设计筛选。但本例的
   NSSS波动是真实障碍，换成regret门也不会自动解决它。
5. 固定工作成本噪声很小，优先降低它的估计误差作用有限。也不要为通过门槛
   临时取消 CVaR、改95%水平、改变预算或放松阈值；这些改变问题本身。

仅作为量级提示：假设 SE 按 C^-1/2 缩小且当前差值保持，最大SE从1.898降到
0.1805约需1770条公共路径；让0.106的第一/第二名差超过2SE，约需15433条。
这种由16条路径外推的计算非常不可靠，不是样本量承诺或推荐执行规模。
它说明直接按原架构加大一轮运行，未必是合适的下一步。
